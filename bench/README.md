# Token benchmark

The included experiment executes matched AGGE and Godot workflows on fresh fixtures and uses independent engine checks. It counts the exact `o200k_base` tokens in each task prompt, edit command, edit payload or source, and returned output. It excludes setup, tool schemas, discovery, checker construction and output, model reasoning, and API framing. A correct trial completed its change and passed the fixture checks.

| Task | AGGE | Godot 4.5.1 | Difference | Correctness |
| --- | ---: | ---: | ---: | --- |
| Place a 12×8 grid | 102 | 207 | 50.7% fewer with AGGE | Both correct |
| Rename a launch room and preserve its return transition | 82 | 89 | 7.9% fewer with AGGE | Both correct |
| Double horizontal speed while fire is held | 86 | 98 | 12.2% fewer with AGGE | Both correct |
| Slice and paint an eight-frame terrain atlas with collision | 137 | 338 | 59.5% fewer with AGGE | Both correct |
| Rebound at full speed after hitting a wall | 84 | 129 | 34.9% fewer with AGGE | Both correct |
| Create a six-frame one-shot animation | 101 | 198 | 49.0% fewer with AGGE | Both correct |

The Godot grid workflow saves a PackedScene generated by a GDScript loop. Its rename, sprint, and rebound workflows use Python to make targeted file edits. AGGE uses one typed operation for each task and a three-operation batch for the atlas. The checkers verify grid positions, launch and return transitions, preserved movement and shield state, atlas frame coordinates and tile collision, the ball's position and velocity after a hit, and the sprite regions, timing, and final hold of a one-shot clip. Both engines passed all six independent checkers. [Recorded transcripts](results.json)

This experiment measures scripted edit transcripts. Live model-session savings, broader success rates, and the 80–90% target remain unverified.

## Reproduce

Build AGGE and install the pinned tokenizer. Use the Godot 4.5.1 executable, with the console variant on Windows. [Godot release archive](https://godotengine.org/download/archive/4.5.1-stable/) · [Tokenizer](https://github.com/openai/tiktoken)

```sh
cargo build -p agge --release --locked
python -m pip install -r bench/requirements.txt
python bench/run.py --agge target/release/agge --godot /path/to/godot --output results.json
```

On Windows use `target/release/agge.exe`. The harness creates fresh temporary fixtures and exits nonzero if a check fails.

## Measure model sessions

Seed fresh fixtures with `python bench/agent_trials.py seed ENGINE TASK DIRECTORY`. Use `agge` or `godot` for the engine and `grid`, `rename`, `sprint`, `atlas`, `bounce`, or `clip` for the task. The command prints the shared prompt. Give the agent the fixture and the relevant engine entry point, with the same model version, configuration, and budget in both arms. Save the complete usage log. Keep timeouts and failed sessions in the sample.

The paired Codex launcher uses fresh directories, alternates engine order, runs independent checks, and keeps prompts and usage logs in its output folder.

```sh
python bench/codex_trials.py --agge target/release/agge --godot /path/to/godot --model MODEL --output target/paired-trials
```

A Windows pilot ran one pair each for grid, rename, sprint, and atlas. The independent checkers passed zero of eight fixtures. The runner blocked local tool calls in both engine arms, three other sessions failed workspace routing, and one timed out. Four sessions reported usage. This pilot provides no successful-run token comparison. [Pilot trial records](codex-pilot.json)

Check the resulting project with `python bench/agent_trials.py check ENGINE TASK DIRECTORY BINARY`. Record the runner's completion status and the checker result for each attempt. Build a JSON array of trial records and summarize it with `python bench/agent_trials.py report trials.json`.

```json
[
  {
    "model": "pinned-model",
    "task": "grid",
    "engine": "agge",
    "trial": "1",
    "log": "agge-grid-01.jsonl",
    "format": "codex",
    "completed": true,
    "correct": true
  }
]
```

The `codex` format reads usage from `turn.completed` events in a JSONL log. Other runners can use `normalized` with a log object containing aggregate `input_tokens`, `output_tokens`, and optional `cached_input_tokens`. Total input includes cached input. The report groups by model, task, and engine and keeps completion, correctness, all-run token usage, and successful-run token usage visible. No provider or API credential is required to summarize logs.


## Replay throughput

The replay timing harness generates projects and input schedules in temporary directories. It verifies held movement and press counts on every run. It alternates the order of the supplied binaries, warms each binary for each fixture, and reports the median and individual elapsed times. Timings include process startup and parsing.

```sh
cargo build -p agge --release --locked
python bench/replay_speed.py /path/to/previous/agge target/release/agge
```

Pass a single binary to measure a build on its own. On Windows use the respective `agge.exe` paths. The default is seven measured runs per fixture and binary.

| Replay workload | Previous span scan | Scheduled input transitions |
| --- | ---: | ---: |
| 3,000 ticks and 30 input spans | 6.05 ms | 5.99 ms |
| 60,000 ticks and 4,096 input spans | 154.75 ms | 28.46 ms |

Windows release builds measured on an AMD Ryzen 7 7700X. Each fixture runs a single scripted entity and measures replay input handling plus simulation. Rendering and larger scene workloads require separate measurements.

The `collision` case runs 240 ticks with 256 movers and 512 solid objects. It verifies the final position of every mover. An earlier Windows release build's median was 35.40 ms across seven runs on the same CPU. The new comparison below uses revision `70cd11a` as its baseline.
